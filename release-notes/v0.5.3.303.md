add wbi_type=2 to commentsPage query items


B站 silently changed the /x/v2/reply/wbi/main endpoint to
require wbi_type=2 in the query string. Without it the request
hangs at the routing layer (no 4xx/5xx, just no response), which
is why the in-app comments fetch appeared as 'fetching forever'
even on the latest build with all the recent WBI retry fixes
applied.

Diagnosis path (2026-08-02):
- Safari probed the same endpoint with different query items.
  Without wbi_type, every variant errored or hung; only
  the URL carrying wbi_type=2 returned a JSON envelope
  (got -403, expected without a cookie).
- playurl (also WBI-signed) still works because that path
  predates the wbi_type split and B站 hasn't (yet) added
  the parameter there.
- /x/space/nav/num was already retired upstream earlier —
  the comments endpoint is the next in a series of silent
  endpoint updates B站 has been pushing.

Always-required parameter for this path as of mid-2026. The
endpoint silently hangs without it.
