send iOS identity headers on every B站 host


The previous buildSignedRequest only sent `mobi_app=iphone`
and `platform=ios` headers when the host was `app.bilibili.com`.
For `api.bilibili.com` (the web API host that commentsPage
hits) it only sent an `Origin` header.

That is the bug. The official B站 iOS client attaches
those iOS identity headers to every B站 request regardless
of the host. B站's server uses the presence of those
headers as part of its content gating logic: with
`mobi_app=iphone` and `platform=ios` present the server
returns the full comments list, without them the server
returns 200 OK with a valid cursor but an empty `replies`
list — the canonical half-authenticated state that we
catch as `BilibiliAPIError.missingIdentity` and surface
as 评论加载失败.

Manual verification: the official B站 iOS app installed
on the same iPad, viewing the same video, sees the full
comment list. The v0.5.7 build 307 diagnostic for the
same video showed `replies items=0 ... allCount=75` and a
clean `nextOffset` cursor — i.e. the server withheld
content but pretended the request succeeded. The
WBI sign passed (code 0, 200 OK) so the request-side fix
in the previous round (v0.5.6 build 306) was necessary
but not sufficient.

The fix: send `mobi_app=iphone` and `platform=ios` on
every B站 request, regardless of host. The per-host
`Origin` header is kept as a supplementary signal for
the `api.bilibili.com` path.

No other behavior change. The change is local to
buildSignedRequest and affects all GET endpoints that
flow through `get<T>`.
