capture real buvid3 for anonymous users


BilibiliAPIClient.generateMobileBuvid used a hard-coded
"Paladala-iOS-Device-Seed" shared by every Paladala install.
The B station server fingerprints that seed and silently gates
comment content for anonymous users, even when all other request
characteristics (User-Agent, Accept headers, Origin, mobi_app,
platform) match the official iOS client shape. The Mac browser
and iPhone official app both fetch a real per-install buvid3
from /x/frontend/finger/spi on first launch and reuse it across
requests; Paladala needs to do the same to escape the silent gate.

Fetch the SPI device-fingerprint pair on first launch via
BilibiliAuthAPI.fetchDeviceID and persist the buvid3 plus buvid4
to UserDefaults under paladala.device.buvid3 and
paladala.device.buvid4. UserDefaults is wiped with the app
bundle, so a fresh install triggers a new capture. The
BilibiliAPIClient anonymous fallback now prefers the persisted
real fingerprint over the hard-coded seed; the hard-coded
generateMobileBuvid path is kept only as a last-resort fallback
during the few-hundred-ms window before the launch fetch
completes.

The previous two attempts (TV-QR-login and auto-show-login-
sheet) targeted the wrong fix direction: the user does not
need to sign in to read comments, the client just needs a real
per-install device fingerprint. Those two commits are
reverted in this branch (v0.5.16 revert 34ff51cf, v0.5.17
revert 064ab928). The v0.5.15 chain fix that lets the WBI
endpoint accept the .pn(1) start cursor as a silent-gate
fallback is kept.
