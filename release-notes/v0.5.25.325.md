Diag/*.swift compile errors after pbxproj wiring


Build #608 (b6426222) compiled past pbxproj (Diag files
were found and the Sources phase emitted them) and into
swift type checking, where three files failed:

  Diag/HMAC.swift:28:19:
    error: cannot specialize non-generic type 'HMAC'
  Diag/ReporterGate.swift:43:38:
    error: cannot convert value of type '[Any]' to
    expected argument type 'Dictionary<String, Any>.Keys'
  Diag/ErrorSink.swift:46/49/79/82:
    error: main actor-isolated property 'systemVersion' /
    'model' / 'current' can not be referenced from a
    nonisolated context  (x6)

Fixes:

1. HMAC.swift
   Renamed the local `enum HMAC` to `enum HMACSigner`.
   Inside the body, `HMAC<SHA256>.authenticationCode(...)`
   was resolving to the local non-generic enum first, so
   the `HMAC<SHA256>` specialization failed. Changing the
   self name frees up `HMAC<SHA256>` to resolve to
   `CryptoKit.HMAC<SHA256>`, and the body now uses
   `CryptoKit.HMAC<SHA256>.authenticationCode(...)`
   explicitly so the resolution is unambiguous regardless
   of import order. The only call site (LogReporter.swift:77)
   is updated from `HMAC.sha256Hex(...)` to
   `HMACSigner.sha256Hex(...)`.

2. ReporterGate.swift
   The old `(details?.keys ?? []).map { $0.lowercased() }`
   bridged `Dictionary<String, Any>.Keys?` to `[Any]` via
   the empty-array literal, which the compiler rejected
   ("cannot convert value of type '[Any]' to expected
   argument type 'Dictionary<String, Any>.Keys'").
   `details?.keys.map { $0.lowercased() } ?? []` is the
   type-correct form: `.map` on an optional unwraps it
   and `?? []` falls back to a clean empty array.

3. ErrorSink.swift
   Both `maybeReport(...)` overloads access
   `UIDevice.current.systemVersion` / `.model`. Swift 6
   marks `UIDevice.current` as main-actor-isolated, so
   the static funcs must declare `@MainActor` to read
   those properties. Both call sites
   (`AppErrorCenter.log` in AppErrorCenter.swift and
   `DiagnosticLogger.log` in DiagnosticLogger.swift) are
   already inside `@MainActor`-isolated classes, so the
   new annotation does not require any caller change.
   The actual report hand-off still happens via
   `Task.detached { ... }` so the LogReporter actor
   itself runs off the main thread as before.

No new types, no protocol changes, no Sources phase
tweak. CI re-runs; this is the last class of issue from
the portal wiring chain.
