TV-endpoint login (introduced for access_key) is a dead end
for comments: B站 classifies the TV-paired SESSDATA and
access_token as "TV client", and the comments endpoint
silently returns `replies: null` for TV-classified callers
— verified 2026-08-02 on the user's iPad with the legacy
/x/v2/reply (255KB response, replies null) and the appkey
+sign path (code 0, replies null), while anonymous and
web-classified requests return real reply lists.

The open-source Flutter client guozhigq/pilipala gets full
comment threads against the same B站 back-end using web-
classified SESSDATA + the legacy /x/v2/reply endpoint. So:

  - LoginViewModel.start()  → webQrcodeGenerate()
  - pollLoop()              → webQrcodePoll()
  - completeLogin()         → accessKey: nil (web flow has none;
    the appkey+sign path stays as forward-compat fallback)

Users must log out and re-scan (web QR) once, so their
persisted SESSDATA is re-issued as a web-session cookie.
