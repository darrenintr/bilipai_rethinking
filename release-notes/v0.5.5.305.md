drop dollar-brace-brace patterns from run-block comments


The previous attempt (a08832b3) still failed workflow
validation, but this time with a different error:
the GitHub Actions YAML parser scans every line of a
block scalar (including bash comments) for workflow
expressions. Any literal dollar-brace-brace token
inside a comment is evaluated, and a placeholder like
three-dots is rejected as an unknown expression
token, which fails the entire workflow.

Real symptom from build run 576:

  Invalid workflow file: .github/workflows/ios-unsigned-ipa.yml
  (Line: 584, Col: 14): Unexpected symbol: ...
  Located at position 1 within expression: ...

The reported line is the start of the run block; the
actual offending token was in a comment a few lines
below, which the GH Actions expression parser still
inspects. The previous heredoc attempt (e996d2d5) had
the same class of problem for a slightly different
reason.

Fix: rephrased both explanatory comments to avoid the
literal dollar-brace-brace pattern. The bash code
itself is unchanged (git log -1 --format=B only, no
env-driven message capture).

Note: do NOT reintroduce dollar-brace-brace in any
comment inside a run block - the parser will still try
to evaluate it and reject placeholder patterns.
