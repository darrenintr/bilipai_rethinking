add request headers + 10s timeout for web API calls


Web client works fine for the same aid that the app hangs on
(verified manually in logged-in Safari). The web request carries
Accept, Accept-Language, Accept-Encoding, and Origin headers;
the iOS app request did not. With bili-universal/iphone UA but
no Accept, B站 server was holding the connection open instead of
returning 4xx, producing the silent-hang pattern we saw in the
diagnostic report.

Add the missing canonical web headers to every api.bilibili.com
request and set a 10s per-request timeout. The URLSession config
has waitsForConnectivity = true with no hard timeout, so a
hung request would never surface; the new timeout is the safety
net so the user sees the error banner instead of an eternal
spinner.

Also add request-side diagnostic logs around the URLSession data
call (sending, sent, failed) so any future hang leaves a trace
in the diagnostic file. The bpLog on the caller side (fetching
on commentsPage) already fires before; the matching sent/failed
log distinguishes URLSession timeout from server-side hang.

Changes:
- buildSignedRequest: add Accept, Accept-Language, Origin (for
  non-app hosts), and request.timeoutInterval = 10
- get: log GET sending / GET sent status=NNN bytes=NNN around
  session.data, plus GET failed error=... for the catch branch

Diagnostic: build 0.5.5.305 still hung silently on the same
aid (no GET sent / no GET failed). After this change, the same
hang will either (a) succeed because B站 no longer hangs the
request, or (b) surface a GET failed error=URLError timedOut
after 10s so the user sees the error banner.
